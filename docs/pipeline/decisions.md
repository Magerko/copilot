# Лог решений

Append-only. Прошлые записи не редактируем.

## 2026-10-27 — Имя продукта: Kairos M
**Контекст:** пользователь попросил имя без «Mager», с отдельной буквой «М».
**Решение:** Kairos M. Кайрос — «тот самый момент», что и есть ядро продукта: поймать актуальный вопрос. M — Moment/Meeting, стоит отдельно, как индекс модели.
**Альтернативы:** Sotto M (sotto voce — «вполголоса»), Cue M — первое длиннее по смыслу, второе плохо читается вслух.
**Последствия:** id `kairos-m`, каталог данных `%APPDATA%/kairos-m`.
**Источник:** пользователь, 2026-10-27.

## 2026-10-27 — Хост: Electron вместо Tauri
**Контекст:** на машине нет Rust/MSVC; ТЗ допускает Electron после спайка. Пользователь разрешил выбирать реализацию самостоятельно.
**Решение:** Electron 45 + electron-vite + React 19.
**Альтернативы:** Tauri 2 — ставить Rust + VS Build Tools (~6 ГБ) и писать нативный оверлей/WASAPI руками; выигрыш в RAM, проигрыш в сроках и риске.
**Последствия:** все пять рисков S1 закрыты штатными API (focusable:false + showInactive, setContentProtection, getDisplayMedia audio:'loopback', node:sqlite, safeStorage/DPAPI). Платим памятью: ~450 МБ workingSet в простое против цели ≤ 250 МБ → смягчаем: оверлей и picker создаются лениво, без лишних процессов; отклонение от SLO записано честно.
**Источник:** спайк S1.

## 2026-10-27 — Ключи шифруются через safeStorage (DPAPI), а не Credential Manager
**Контекст:** FR-P06 разрешает Credential Manager / DPAPI. Нативного модуля keytar без MSVC не собрать.
**Решение:** `safeStorage` (DPAPI под пользователем Windows) в отдельном файле `secrets.bin`; в settings/SQLite только `hasKey`.
**Последствия:** секрет привязан к учётке Windows; копия файла на другой машине бесполезна.

## 2026-10-27 — Распознавание: перераспознавание растущего буфера вместо стриминговой ASR
**Контекст:** whisper не стриминговый; ТЗ требует partial ≤ 1.2 с.
**Решение:** VAD в renderer режет реплики; во время речи каждые ~1.2 с растущий буфер отправляется как partial, по концу реплики — final. Partial не пишется в БД.
**Источник:** спайк S2 (задержки).

## 2026-10-27 — ASR: два профиля, CPU base по умолчанию, GPU turbo по выбору
**Контекст:** спайк S2: CPU base 0.6 с (язык задан) / 1.18 с (auto); small 1.9 с; CUDA turbo-q5 ~0.07–0.11 с, но пакет 685 МБ и первый запрос 13–27 с.
**Решение:** профиль «Быстрый (CPU)» = `ggml-base` + `whisper-bin-x64` (b5454); профиль «Точный (NVIDIA)» = `large-v3-turbo-q5_0` + CUDA-сборка, предлагается в онбординге при наличии NVIDIA, прогрев в фоне при запуске. На CPU язык фиксируется после первой уверенной реплики (detected_language_probability ≥ 0.8), чтобы не платить ×2 за auto. Глоссарий терминов передаётся как `prompt`. Тег релиза пинится: `b5454`.
**Альтернативы:** small по умолчанию — не укладывается в 1.2 с на CPU.
**Последствия:** украинский на живой речи не проверен; при выборе uk язык ASR задаётся явно.
**Источник:** спайк S2.

## 2026-10-27 — Автоответ выключен по умолчанию, включается для локальной модели
**Контекст:** при живом слайсе распознанный вопрос «ждал» хоткея — по дефолту `autoAnswer: false`.
**Решение:** оставить: для облачной модели автоответ тратит деньги на каждый ложный «вопрос». Онбординг включает автоответ, если выбрана локальная модель; в оверлее подсказка «Ctrl+Alt+Enter — ответить сразу».
**Альтернативы:** включить всегда — дешевле в объяснении, дороже для пользователя BYOK.

## 2026-10-27 — Прогрев локальной LLM при старте сессии
**Контекст:** первый запрос к Ollama после смены модели — 27.8 с (загрузка в VRAM); таймаут первого токена тестового запроса был 30 с.
**Решение:** при старте сессии для локальной quick_answer-модели уходит запрос на 1 токен (как прогрев ASR); тест соединения для loopback-провайдера ждёт до 120 с.
**Последствия:** первый вопрос сессии отвечается за доли секунды, а не за полминуты.

## 2026-10-27 — Компактный оверлей подстраивает высоту под ответ
**Контекст:** в фиксированных 220 px ответ обрезался, тезисы были ниже края без признака прокрутки.
**Решение:** compact растёт по содержимому в пределах 120–440 px (ResizeObserver → `km:overlay:fit`); expanded сохраняет размер пользователя.

## 2026-10-27 — Без резюме тезисы не содержат конкретных цифр и названий
**Контекст:** без CV модель написала в тезисах «увеличили производительность в 10 раз».
**Решение:** правило «не выдумывать числа/даты/компании/продукты, которых нет в блоках данных» + пометка `[нет в резюме]` для утверждений о прошлом пользователя; гипотетические вопросы («как бы вы…») — без пометки. `PROMPT_VERSION km-2026-10-27.2`.
**Последствия:** 14B-модель иногда ставит пометку и на гипотетический вопрос — лучше лишняя пометка, чем выдуманный факт.

## 2026-10-28 — @napi-rs/canvas остаётся в сборке
**Контекст:** хотелось вырезать 37 МБ: для извлечения текста canvas не нужен.
**Решение:** оставить. Проверка показала: без него pdfjs-dist 5 падает при загрузке (`DOMMatrix is not defined`) — импорт PDF-резюме сломался бы. Добавлен тест на реальный PDF/DOCX. Вырезаны только лишние локали Chromium (`electronLanguages: ru, uk, en-US`).

## 2026-10-28 — Форматирование: prettier с конфигом под стиль проекта
**Решение:** `.prettierrc` (без `;`, одинарные кавычки, ширина 160), весь `src/` и `tests/` отформатированы одним проходом — истории git ещё нет, шума в диффах не будет.

## 2026-10-28 — Язык разговора задаётся явно; авто-фиксация убрана
**Контекст:** аудит: auto на CPU — 1.29–1.40 с (AC-7 FAIL), а фиксация языка по первой реплике превращала речь на другом языке в перевод.
**Решение:** в онбординге «Язык разговора» (по умолчанию = язык интерфейса, `asr.language: 'ru'` в дефолтах); «Смешанный — автоопределение (медленнее)» — осознанный выбор. Каждая final-реплика пишет `asr_latency` в диагностику.
**Альтернативы:** оставить фиксацию — быстро, но искажает транскрипт; auto всегда — честно, но медленно.
**Последствия:** с явным языком 0.88–0.98 с (≤ 1.2 с). Двуязычное интервью требует режима «Смешанный».

## 2026-10-28 — Статусы показывают проверенное, а не настроенное
**Решение:** LLM зелёный только после успешного ответа или проверки соединения; защита экрана никогда не зелёная — Windows не сообщает, соблюдает ли флаг программа захвата.

## 2026-10-28 — Согласия только явным действием
**Решение:** захват — по «Далее» на шаге «Звук» и только для включённых источников; облако — отдельный переключатель; снимки экрана проверяются в main, а не только в UI. Fallback на облачного провайдера проходит ту же проверку `consent.cloud`.

## 2026-10-28 — Трей и защита окон от захвата, но без маскировки процесса
**Контекст:** пользователь попросил сворачивать в трей и «маскироваться в трее и диспетчере задач под что-то» — на случай, если на видео-звонке попросят показать экран.
**Решение:** сделано только то, что не нарушает non-goals ТЗ («скрытие процесса», «невидимость как обещание»):
- сворачивание в трей при закрытии/сворачивании (`window.minimizeToTray`, по умолчанию вкл.) — сессия продолжает работать, полный выход через меню трея;
- защита от захвата расширена с оверлея на главное окно и picker (`window.protectFromCapture`, по умолчанию вкл.) — при демонстрации экрана окна Kairos M не попадают в поток (WDA_EXCLUDEFROMCAPTURE), но пользователь их видит. Статус честный, невидимость не обещается.
**Отклонено:** переименование/маскировка процесса в диспетчере задач под чужой. Это приём уклонения от обнаружения: он выдаёт exe за другой процесс, чтобы человек или ПО контроля не поняли, что запущено. Противоречит ТЗ и принципу «не врать о том, что запущено»; при обнаружении выглядит как умышленный обман и практической защиты на прокторинге не даёт. Имя процесса остаётся `Kairos M`.
**Последствия:** реальная задача пользователя (не светить помощника при шаринге экрана) закрыта защитой от захвата + треем + «Паникой», честными средствами.

## 2026-10-28 — Оверлей: полупрозрачный фон, текст остаётся чётким
**Контекст:** запрос пользователя — сделать окно с текстом полупрозрачным. Ползунок «Прозрачность» (setOpacity на всё окно) уже был, но он гасил и текст.
**Решение:** окно оверлея сделано `transparent: true` без непрозрачного фона; полупрозрачность несёт сам фон панели через CSS `color-mix(... var(--bg-alpha) ...)`, а текст остаётся непрозрачным. Ползунок «Непрозрачность фона» 15–100% управляет только альфой фона. `setOpacity` больше не используется.
**Проверка:** при 40% фон просвечивает, текст чёткий; перетаскивание (`-webkit-app-region: drag`), кнопки и смена размера (compact-автоподгон 303→560 при «развернуть») работают на прозрачном окне.
**Последствия:** `hasShadow` у прозрачного окна игнорируется Windows — тень убрана, добавлен `border-radius`. Контент-чипы (блоки кода/ответа) остаются чуть плотнее фона — так читаемее.
